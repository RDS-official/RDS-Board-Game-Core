# 璀璨宝石 · 牌组与操作重设计

> 范围：packages/games/src/splendor（当前为「宝可梦璀璨宝石」主题）与 ?zones 操作台。
> 性质：**设计方案 + 动作族实现记录**。目标是把「取任意三种不同筹码＝遍历所有组合」改成
> 「一个动作 + 一个筹码选择器」。
>
> 2026-11-08 拍板：**宝可梦版本继续作为默认版本，现有牌组/规则不改**；经典 90 张牌组
> 只保留为未来可选方案，不在本次执行。动作族已落地到当前宝可梦牌组。

---

## 0. 结论先行

1. 当前的问题不是「筹码组合太多」，而是**把组合当成了合法动作**：
   TAKE_3_DIFF_GEMS 的每一种颜色组合都是一条 Action，UI 只能把它们全部列出来。
2. 正确做法是**动作族（Action Family）**：
   - 引擎仍可保留具体组合，供 AI / 回放使用；
   - Presenter 把同一动作族的 N 条组合塌缩成 **1 张 UI 动作**；
   - 玩家在筹码选择器里选颜色，UI 再用「颜色集合 → 具体 Action」的映射派发。
3. **本轮不重建牌组**：保留现有宝可梦版本（6 色、100 张、稀有/传说/Mega/宝可梦商店）作为默认；经典 90 张牌组方案仅作为未来可选，不在本次执行。
4. 操作上：**不再有「结束回合」**。璀璨宝石每回合恰好一个动作；拿筹码、买卡、保留卡三者选一，
   结算后自动换人。

## 1. 当前实现审查

### 1.1 牌组现状

| 项 | 当前 | 经典璀璨宝石 |
| --- | ---: | ---: |
| 可拿取的宝石色 | 6（含紫色大师球） | 5 + 黄金 |
| 发展卡 | 100 张（s1 35 / s2 30 / s3 15 / rare 10 / legend 10） | 90 张（40 / 30 / 20） |
| 额外牌 | Mega 10、Poké Mart 30 | 无 |
| 贵族 | 无独立贵族牌 | 10 张，3 分 |
| 胜利分 | 18 / Mega 20 | 15 |
| 黄金 | 紫色大师球可被拿取 | 黄金只能通过保留获得，作万能支付 |

结论：当前是「宝可梦主题 + 多项扩展开关」。按 2026-11-08 拍板，它继续作为默认版本；
经典牌组不替换。

### 1.2 动作现状

packages/games/src/splendor/rules.ts 的 getLegalActions：

- TAKE_3_DIFF_GEMS：对 available 颜色做 combinations(available, size)，每个组合一条 Action；
- TAKE_2_SAME_GEMS：每种可双取颜色一条 Action；
- BUY_CARD：每张市场/保留卡一条（可接受，卡是实体对象）；
- RESERVE_CARD：每张明牌 + 每个牌堆盲抽一条；
- EVOLVE / MEGA_EVOLVE：每个进化选项一条；
- TAKE_MEGA_TOKEN：一条；
- END_TURN：当前作为死锁逃生。

以 5 种可拿颜色为例：

~~~
C(5,3) = 10 条 TAKE_3
5 条 TAKE_2
约 12 条 BUY
约 15 条 RESERVE
+ 进化/系统
= 40+ 条合法动作
~~~

UI 在 ?zones 下只能显示「前 4 条 + 更多 14」，这不是玩家能理解的「拿三种不同颜色」，
而是把**组合数学**暴露给了玩家。

### 1.3 为什么不能只靠分页

分页只是把组合藏到第二页。玩家仍然要：

- 从 10 个三色组合里找自己想要的；
- 记住哪些组合被「更多」截断；
- 在 40+ 条动作里判断合法性。

真正需要的是**动作族 + 选择器**，不是更好的分页。

## 2. 经典璀璨宝石规则基线

### 2.1 人数与资源

| 人数 | 每种宝石筹码 | 黄金 | 贵族数 |
| ---: | ---: | ---: | ---: |
| 2 | 4 | 5 | 3 |
| 3 | 5 | 5 | 4 |
| 4 | 7 | 5 | 5 |

- 5 种宝石色：红、蓝、绿、黑、白（主题皮肤可改名，但**只有 5 种可拿色**）。
- 黄金是万能替代，不能主动拿取；只能通过「保留卡」获得 1 个。
- 每回合恰好执行一个动作：拿筹码 / 买卡 / 保留卡。
- 手牌（保留区）上限 3 张；保留卡对对手隐藏。
- 15 分触发最后一轮；回合数补完后最高分获胜；同分时发展卡数量少者胜（可按项目规则简化）。

### 2.2 发展卡

| 阶 | 张数 | 每色张数 | 分数 | 费用总量 | 奖励 |
| --- | ---: | ---: | --- | --- | --- |
| 1 | 40 | 8 | 0–1 | 3–4 | 1 个同色奖励 |
| 2 | 30 | 6 | 1–3 | 5–7 | 1 个同色奖励 |
| 3 | 20 | 4 | 3–5 | 7–14 | 1 个同色奖励 |

- 每阶 4 张明牌；买走立刻从同阶牌堆补 1 张。
- 牌堆耗尽时不再补；明牌可以少于 4 张。
- 购买时：先扣奖励，再扣筹码；黄金补任意缺口。
- 奖励是永久宝石折扣，不消耗。

### 2.3 贵族

- 10 张贵族，每张 3 分。
- 两类要求：
  - 4/4：两种颜色各 4 个奖励；
  - 3/3/3：三种颜色各 3 个奖励。
- 每回合结束（购买/保留/拿筹码后）自动检查；满足即可获得，不消耗行动。
- 一回合最多获得 1 张贵族（经典规则）；若同时满足多张，玩家选择。
- 2/3/4 人分别使用 3/4/5 张。

### 2.4 行动

| 行动 | 规则 | 备注 |
| --- | --- | --- |
| 拿 3 种不同色 | 从银行拿 1–3 种不同颜色各 1 个；银行不足 3 色时可拿更少 | 不能拿黄金 |
| 拿 2 个同色 | 该色银行至少 4 个时，拿 2 个同色 | 不能拿黄金 |
| 保留卡 | 从明牌或牌堆顶拿 1 张进保留区，并获得 1 个黄金；上限 3 | 可保留任意阶 |
| 购买卡 | 支付费用，拿卡进个人 tableau；获得奖励和分数 | 可用黄金替代 |
| 贵族 | 满足条件自动获得 | 不消耗行动 |
| 结束回合 | **不存在** | 每个行动后自动换人 |

## 3. 牌组重设计

### 3.1 数据模型

建议把牌组从「导入的 JSON 卡表」改为「规则数据 + 主题皮肤」两层：

~~~ts
interface SplendorCardDef {
  id: string;
  tier: 1 | 2 | 3;
  bonus: GemColor;          // 5 色之一
  points: 0 | 1 | 2 | 3 | 4 | 5;
  cost: Partial<Record<GemColor, number>>;
  art?: string;             // 主题层
  name?: string;            // 主题层
}

interface SplendorNobleDef {
  id: string;
  points: 3;
  requires: Partial<Record<GemColor, number>>; // 4/4 或 3/3/3
  art?: string;
  name?: string;
}
~~~

- GemColor 固定为 5 色；黄金不是 GemColor，是 WILD。
- 规则层不出现 purple / master ball / mega / rare / legend。
- 主题层（宝可梦）只提供 name/art 映射，不改变费用、分数、奖励和牌数。

### 3.2 牌组配方

建议用「每色 8/6/4 张 + 费用模板」生成 90 张，而不是继续维护 100 张不平衡的导入表。

#### 一阶（40 张 = 5 色 × 8）

| 每色序号 | 分数 | 费用模板 | 说明 |
| ---: | ---: | --- | --- |
| 1 | 0 | 同色 2 + 异色 1 | 最便宜的入门卡 |
| 2 | 0 | 同色 3 | 单色 3 |
| 3 | 0 | 异色 2 + 异色 1 | 双色 3 |
| 4 | 0 | 异色 2 + 异色 2 | 双色 4 |
| 5 | 0 | 三色 1/1/1 | 三色 3 |
| 6 | 0 | 三色 1/1/2 | 三色 4 |
| 7 | 0 | 四色 1/1/1/1 | 四色 4 |
| 8 | 1 | 同色 4 | 一阶高分卡 |

> 费用模板中的「同色」指该卡奖励色；每色轮换，避免某色过强。
> 一阶总费用控制在 3–4，保证开局 2–3 回合能买第一张。

#### 二阶（30 张 = 5 色 × 6）

| 每色序号 | 分数 | 费用模板 |
| ---: | ---: | --- |
| 1 | 1 | 同色 3 + 异色 2 |
| 2 | 1 | 同色 4 + 异色 1 |
| 3 | 2 | 同色 5 |
| 4 | 2 | 三色 2/2/1 |
| 5 | 3 | 四色 2/1/1/1 |
| 6 | 3 | 同色 6 |

#### 三阶（20 张 = 5 色 × 4）

| 每色序号 | 分数 | 费用模板 |
| ---: | ---: | --- |
| 1 | 3 | 同色 7 |
| 2 | 4 | 三色 3/3/3 |
| 3 | 4 | 四色 3/2/2/2 |
| 4 | 5 | 同色 8 + 异色 2 |

> 三阶费用 7–14，保证 15 分终局有足够张力；5 分卡每色 1 张。
> 这些是**配方模板**，实现时建议用固定 90 条数据表，便于平衡审查和回放。

#### 贵族（10 张）

| 类型 | 张数 | 要求 |
| --- | ---: | --- |
| 4/4 | 5 | 两种颜色各 4 奖励 |
| 3/3/3 | 5 | 三种颜色各 3 奖励 |

- 10 张贵族覆盖 5 色的组合，避免重复；
- 2/3/4 人随机取 3/4/5 张（setup 时用 PRNG 洗牌）；
- 贵族不进入市场，单独展示在桌面侧。

### 3.3 宝可梦主题怎么处理

推荐：

- **规则层用经典 Splendor**：5 色、90 张、10 贵族、15 分。
- **主题层做皮肤**：5 种精灵球颜色对应 5 宝石色；黄金 = 大师球；
  卡名/卡图取宝可梦，但费用、分数、奖励完全按经典表。
- 现有 pokemonData.json 的 100 张卡不再作为默认牌组：
  - 保留为 variant = 'pokemon' 的扩展数据；
  - 或抽取 90 张映射到经典费用模板，作为主题皮肤。

这样既保留 IP 视觉，又不会出现「6 色 + Mega + Poké Mart」把基础规则撑爆的问题。

## 4. 操作逻辑重设计

### 4.1 核心：动作族（Action Family）

不要改引擎的合法动作生成方式（AI 需要具体动作），而是在 Presenter 增加**动作族塌缩**：

~~~
引擎 legalActions:
  TAKE_3_DIFF_GEMS [红蓝黑]
  TAKE_3_DIFF_GEMS [红蓝白]
  ... 10 条

Presenter:
  1 条 UI 动作「拿取精灵球」
  + 选择器：颜色 5 个、min 1、max 3、distinct
  + variantMap: 颜色集合 -> 具体 Action
~~~

这和 buildActionsView 已有的「一张杀 × N 个目标 → 一张杀 + 目标选择器」是同一模式，
只是把 targetVariants 泛化为 **variantKey -> Action**。

#### 数据结构建议

~~~ts
interface BoundAction {
  ui: UiAction;
  action?: Action;
  targetVariants?: Map<string, Action>;   // 目标塌缩
  variantKey?: 'gems' | 'gem' | 'evolution' | 'card';
  variantVariants?: Map<string, Action>;  // 动作族塌缩
}

interface UiAction {
  // ...现有字段
  fields?: UiActionField[];
  family?: string;  // 动作族 id，便于探针与排序
}
~~~

UiActionField 增加一个通用 widget：

~~~ts
type UiFieldWidget = 'slider' | 'token-picker';
~~~

token-picker 读取：

- options: [{ value: 'red', label: '红', count: 7, disabled: false }]
- min / max;
- distinct: true（三色）或 false（双取同色）；
- 当前选择值是一个 string[]，提交到 payload。

这样通用层不需要知道「璀璨宝石」四个字，任何「从一组离散资源里选 N 个」的游戏都能用。

### 4.2 动作族清单

| 动作族 | UI 动作 | 选择器 | variant key | 说明 |
| --- | --- | --- | --- | --- |
| 三色 | 拿取精灵球 | token-picker，min 1 max 3 distinct | 排序后的颜色集合 | 银行不足 3 色时允许 1–2 |
| 双取 | 双取同色 | token-picker，min 2 max 2 same | 颜色 | 仅银行 ≥4 的颜色可选 |
| 购买 | 购买 | 点市场卡/保留卡 → 支付面板 | cardId | 一张卡一条，不再拆动作 |
| 保留 | 保留 | 点市场卡/牌堆 → 确认 | cardId / tier | 附赠黄金 |
| 进化 | 进化 | 选择器（若有多项） | 进化 key | 宝可梦变体才需要 |
| 贵族 | 无动作 | 自动结算 | nobleId | 不消耗行动 |

### 4.3 「拿取精灵球」面板

线框：

~~~
┌─ 拿取精灵球 ───────────────────────────────────────────┐
│  [ 3 种不同 ]  [ 2 个同色 ]                          │
│                                                        │
│   🔴 红 7   🔵 蓝 5   ⚫ 黑 4   💗 粉 2   🟡 黄 0     │
│   [✓]      [✓]       [✓]       [ ]       [禁用]      │
│                                                        │
│   已选 3 / 3 种不同颜色                               │
│   [清空]                                  [确认拿取]  │
└────────────────────────────────────────────────────────┘
~~~

规则：

- 「3 种不同」最多选 3 个，不能重复；银行 0 的颜色禁用；
- 银行不足 3 色时自动把 max 降到可用颜色数，允许拿 1–2 种；
- 「2 个同色」只显示银行 ≥4 的颜色；选中 1 个即可确认；
- 玩家筹码 + 选择数 ≤ 10；超过时禁用对应颜色并说明；
- 确认后一次 dispatch；取消不改变状态；
- 选择器显示银行剩余数量，玩家不需要自己数。

### 4.4 购买面板

点击市场卡/保留卡 → 卡详情 + 支付预览：

~~~
┌─ 妙蛙种子 · 二阶 ──────────────────────────────┐
│ 奖励：绿 +1    分数：2                          │
│ 费用：绿 3  蓝 2  红 1                         │
│ 你的奖励：绿 1  蓝 0  红 0                     │
│ 实际支付：绿 2  蓝 2  红 1                     │
│ 黄金替代：0（可用 2）                          │
│                                  [取消] [购买]  │
└────────────────────────────────────────────────┘
~~~

- 先扣奖励，再扣筹码；不足部分由黄金补；
- 黄金替代数量默认最小，玩家可以调整（如果多解）；
- 购买后卡进 tableau，奖励立即生效，分数累加；
- 不可购买时显示缺口（差 1 蓝、差 2 黄金），不显示灰色按钮无原因。

### 4.5 保留面板

- 明牌：点击卡 → 「保留」；获得 1 黄金；
- 牌堆：点击牌堆 → 选择阶 → 随机保留顶牌；
- 保留上限 3；达到上限时按钮禁用并说明；
- 保留卡对对手隐藏；只在自己的手牌/保留区显示卡面；
- 保留不消耗黄金，反而获得黄金。

### 4.6 回合流

- 每个动作执行后自动检查贵族 → 自动换人；
- 没有「结束回合」按钮；
- 若玩家无合法动作（理论上不应发生），由引擎给出错误/死锁提示，不暴露 END_TURN 作为常规动作；
- 15 分触发最后一轮：完成当前轮后结算；UI 显示「最后一轮」。

### 4.7 贵族

- 桌面侧展示 3/4/5 张贵族；
- 每张显示 3 分与要求；
- 玩家卡上显示进度：4/4 红蓝、3/3/3 红蓝绿；
- 满足时回合结束自动获得；若同时满足多张，弹出选择；
- 不进入动作列表，不占手牌，不占行动。

组合只存在于选择器的状态里，不存在于 snapshot.actions 的可见列表里。

## 6. 规则校验

在 reducer 侧保留最终裁决：

- 三色：颜色数 1–3、互不重复、银行各 ≥1、玩家筹码 + 数量 ≤10；
- 双取：颜色银行 ≥4、玩家筹码 + 2 ≤10；
- 不能拿黄金；
- 保留：保留区 <3、目标卡在明牌/牌堆；
- 购买：奖励折扣后支付、黄金补足、卡在合法来源；
- 贵族：奖励计数满足、每回合最多 1 张；
- 15 分终局：触发轮结束，不由 UI 判断。

UI 的 token-picker 只做预置灰与计数；最终合法性仍由引擎判定。

### 7.2 已落地（2026-11-08）

- 保留宝可梦牌组与规则；不改 100 张卡表、6 色、Mega/Poké Mart。
- 引擎仍逐条返回 TAKE_3_DIFF_GEMS / TAKE_2_SAME_GEMS 具体动作，AI/回放不变。
- Presenter 通过动作族 TAKE_GEMS / TAKE_DOUBLE 把组合塌缩为一个 UI 按钮：
  - TAKE_GEMS：颜色复选框，min/max 为本次可拿数量；
  - TAKE_DOUBLE：颜色选择器，只列银行 ≥4 的颜色。
- perform 用颜色集合的排序 key 找回具体动作，reducer 仍做最终合法性校验。
- pnpm probe:operation-deck 增加三色动作族、双取动作族、选择三种颜色一次派发的断言。

### 7.1 与手牌操作台的关系

- 拿取动作在 #op-context / 交易面板，不进手牌；
