# 三国杀 · 多模式规则集与实现说明

本文件是 `packages/games/src/sanguosha` 的可执行规则集说明。规则语义以
[三国杀官方规则集 3.0](https://gltjk.com/sanguosha/rules/) 为准；本实现覆盖
4/5/8 人标准身份局、4 人 2v2 对抗、2–8 人“杀下家”村规，以及带有内置 AI 的单机/房间对局。
所有规则都拆成内核可以哈希、回放和投影的纯状态转移。

> 相关入口：`packages/games/src/sanguosha/setup.ts`（初始局面）、`cards.ts`（牌表）、
> `heroes.ts`（武将表）、`legal.ts`（合法动作）、`resolve.ts`（结算）、`outcome.ts`（胜负）、
> `presentation.ts`（表现声明）、`hooks.ts`（装备规则切面）。
>
> 规则参考页：[游戏流程](https://gltjk.com/sanguosha/rules/flow/game.html)、
> [使用事件结算](https://gltjk.com/sanguosha/rules/flow/use.html)、

## 1. 实现范围

| 项目 | 实现 |
| --- | --- |
| 模式 | 身份局 4–8 人（标准 5/8 人）；4 人 2v2 对抗；2–8 人杀下家村规 |
| 座位 | `seatRange = { min: 2, max: 8, default: 4, variable: true }`，由房间按场景选择人数 |
| 身份局编制 | 4 人 1主1忠1反1内；5 人 1主1忠2反1内；8 人 1主2忠4反1内 |
| 牌堆 | 标准 108 张；可选军争 52 张，共 160 张（`military` 场景） |
| 阶段 | 准备、判定、摸牌、出牌、弃牌、结束六阶段 |
| 基础牌 | 杀、火杀、雷杀、闪、桃、酒 |
| 锦囊牌 | 过河拆桥、顺手牵羊、决斗、借刀杀人、无中生有、无懈可击、南蛮入侵、万箭齐发、桃园结义、五谷丰登、铁索连环、火攻 |
| 延时锦囊 | 乐不思蜀、闪电、兵粮寸断 |
| 装备 | 武器、防具、+1 坐骑、-1 坐骑 |
| 判定 | 牌堆顶真实牌判定、判定区展示、八卦阵规则钩子 |
| 伤害 | 普通 / 火焰 / 雷电、铁索传导、伤害来源、濒死、死亡奖励与惩罚 |
| 武将 | 17 名标准武将，见 §7 |
| AI | 房间可添加 AI 补位；单机 `ai_standard_4` 场景为 1 真人 + 3 AI；AI 与真人走同一 `legalActions → dispatch` 管线 |
| 积分 | 身份局/4人对抗胜 +500、负 -500；内奸单独获胜 +1000；杀下家胜 +250、负 -250 |
| 回放 | 一次 `reduce` 只产生一次逻辑跃迁；自动阶段由 `resolveFollowUp` 作为独立动作记录 |

明确不在本夹具内：国战、1V1、3V3、神将、界限突破扩展、全部军争/SP 武将、
木牛流马等宝物牌，以及商业版本的皮肤/语音内容。它们是内容扩展，不是本规则集
的核心状态机；新增时应按 §10 的方式扩展 `cards.ts` / `heroes.ts` / `legal.ts`。

## 2. 座位、身份与胜负

### 2.1 座位

玩家按 `playerOrder = [p1..pN]` 逆时针行动。地图仍是 `ring` 拓扑，但座位节点使用显式
世界坐标（不是固定 90° 的四人环）：四座半径约 8.9×5.6，八座扩大到约 11.6×7.0。

- 相邻座位距离为 1；死亡角色不占距离；
- 任意人数都按实际存活座位环计算距离；
- `+1坐骑` 让其他角色计算与你的距离 +1，`-1坐骑` 让你计算与其他角色的距离 -1；
- 武器决定攻击范围，基础攻击范围为 1。

### 2.2 身份

| token | 名称 | 胜利条件 |
| --- | --- | --- |
| `LORD` | 主公 | 与忠臣一起消灭所有反贼和内奸 |
| `LOYALIST` | 忠臣 | 同上 |
| `REBEL` | 反贼 | 主公死亡（除非场上只剩内奸，此时内奸胜） |
| `SPY` | 内奸 | 成为最后一名存活角色 |
| `TEAM_A` / `TEAM_B` | 赤方 / 蓝方 | 4 人对抗中消灭对方阵营 |
| `KILL_NEXT` | 杀下家 | 杀死自己的下家（或成为最后生还者） |

身份局中主公身份公开，其他身份通过 `GameModule.project.player` 对非本人隐藏；角色阵亡或
游戏结束后身份公开。4 人对抗与杀下家是公开身份模式，`project.player` 不会隐藏阵营。

主公体力上限 +1。经典四人局固定为刘备（主公）、关羽（忠臣）、曹操（反贼）、吕布（内奸）；
5/8 人标准局与其他场景从 17 名武将中无重复随机选将。

### 2.2.1 模式编制

| 模式 | 人数 | 座位角色 |
| --- | --- | --- |
| 身份局 `identity` | 4 | 主、忠、反、内 |
| 身份局 `identity` | 5 | 主、忠、反、反、内 |
| 身份局 `identity` | 8 | 主、忠、忠、反×4、内 |
| 4 人对抗 `team` | 4 | `TEAM_A` / `TEAM_B` 交替，2v2 |
| 杀下家 `kill_next` | 2–8 | 全员 `KILL_NEXT`，按当前下家动态判定 |

房间创建时不选变体、人数不足 4 人时，`setupSanguosha` 自动落到杀下家村规；4 人及以上
落到身份局。正式房间建议显式选择 `identity_5` / `identity_8` / `team_4` / `kill_next`。

### 2.3 胜负判定

`checkSanguoshaWin(state, death?)` 是纯函数：

1. **身份局**：
   - 主公死亡时，若唯一存活者是内奸，内奸胜；否则反贼胜；
   - 主公存活且反贼、内奸全部阵亡：主公与忠臣胜；
   - 其余情况继续游戏。
2. **4 人对抗**：一方两名角色全部阵亡，另一方获胜；双方同时全灭为平局。
3. **杀下家**：伤害来源杀死自己的下家（以死亡前的存活座位环为准）时立即获胜；否则
   只剩最后一名生还者时该角色获胜。下家被第三方或判定伤害杀死不会触发“杀下家”胜利。

### 2.4 积分

积分规则在 `packages/games/src/sanguosha/scoring.ts` 中只写一份，游戏终局幕布与服务器账号
账本共用同一组 delta：

| 模式 | 获胜者 | 失败者 |
| --- | ---: | ---: |
| 身份局 / 4 人对抗 | +500/人 | -500/人 |
| 身份局内奸单独获胜 | +1000 | -500/人 |
| 杀下家村规 | +250 | -250/人 |

积分按上表结算（内奸翻倍局因此不是零和，按规则表原样执行）；终局时写入
`globalVars.scoreDeltas` 和每名角色的 `customProps.points`，服务器按 `roomId` 去重后
累计到账号的 `sanguoshaPoints`，AI 座位不进入账号账本。

## 3. 回合与阶段

```
回合开始前
  → 准备阶段
  → 判定阶段
  → 摸牌阶段
  → 出牌阶段
  → 弃牌阶段
  → 结束阶段
  → 回合结束后
```

实现中 `phase` 的 token 为：

| token | 阶段 | 自动行为 |
| --- | --- | --- |
| `PLAY` | 出牌阶段 | 玩家可出牌、发动主动技、结束回合 |
| `TURN_START` | 准备阶段 | 重置回合标记、洛神等准备阶段技能 |
| `JUDGE` | 判定阶段 | 依次结算判定区的延时锦囊 |
| `DRAW` | 摸牌阶段 | 摸 2 张（英姿 +1；兵粮寸断可跳过） |
| `DISCARD` | 弃牌阶段 | 手牌超过体力值时逐张弃置 |
| `END` | 结束阶段 | 闭月等结束阶段技能，然后移交回合 |

### 3.1 回合开始

- 重置 `strikesUsed`、酒、仁德、制衡、苦肉、青囊、结姻、离间等本回合标记。
- 若武将有洛神：亮出牌堆顶一张牌；黑色则获得并重复，红色则置入弃牌堆。

### 3.2 判定阶段

判定区中的延时锦囊按置入顺序逐张结算：

- `乐不思蜀`：判定不为红桃则跳过出牌阶段；
- `兵粮寸断`：判定不为梅花则跳过摸牌阶段；
- `闪电`：判定为黑桃 2~9 则受到 3 点无来源雷电伤害，否则移动到下家的判定区。

判定牌使用牌堆顶的真实牌（含花色和点数），并写入 `globalVars.lastJudge` 供 UI 展示。
`八卦阵` 使用同一判定入口；`bagua_armor` 钩子把 `JUDGE_BAGUA` 的规则参数写入 payload，
reducer 只执行通用判定。

### 3.3 出牌阶段

每个出牌阶段默认只能使用一张【杀】；`诸葛连弩` 或 `咆哮` 取消此限制。
使用牌后进入结算；响应窗口通过中断栈打开，详见 §5。

### 3.4 弃牌阶段

手牌上限等于当前体力值。玩家逐张选择弃置，直到手牌数**恰好等于**上限；多于上限时
`DISCARD_CARD` 才合法，减到上限后 `resolveFollowUp` 自动进入结束阶段，不能继续弃到 0。
若角色有 `连营`，失去最后一张手牌时摸一张。

### 3.5 结束阶段与回合移交

结束阶段触发 `闭月` 等技能后，`FINISH_TURN` 把行动权交给下一名存活角色；若越过
座位环则 `round += 1`。所有自动阶段都是 `resolveFollowUp()` 返回的独立动作，因此
`actionLog` 和回放逐位一致。

## 5. 结算模型与中断栈

### 5.1 基本流程

内核管线是：

```
validate → decision window → interrupt stack → AOP → reduce → outcome → log
```

本模组把规则语义放在 `reduce` 与 `resolveFollowUp`，不把回调、类实例或随机数生成器
写进状态。所有随机性来自 `state.prngState`：

- 洗牌：`DeterministicPRNG.shuffle`；
- 判定/随机取牌：`DeterministicPRNG.nextInt`；
- 牌堆耗尽时：弃牌堆按当前 `prngState` 洗回牌堆，再把 `nextSeed` 写回状态。

### 5.2 中断栈帧

| 栈帧 | 触发 | 响应者 | 结算 |
| --- | --- | --- | --- |
| `STRIKE_RESOLUTION` | 使用【杀】 | 目标、护驾/激将友军 | 出闪/八卦/放弃；失败执行伤害 |
| `DUEL_RESOLUTION` | 决斗 | 当前应出杀者 | 交替出杀；未出者受伤 |
| `MASS_TRICK_RESOLUTION` | 南蛮入侵/万箭齐发 | 当前目标 | 出杀/闪或受伤 |
| `TRICK_RESOLUTION` | 任意锦囊 | 手里有无懈的角色 | 无懈可击或放弃 |
| `WUXIE_RESOLUTION` | 无懈可击响应 | 手里有无懈的角色 | 可再次无懈；奇数次抵消原锦囊 |
| `JUDGE_TRICK_RESOLUTION` | 判定区延时锦囊生效前 | 手里有无懈的角色 | 无懈可击或放弃 |
| `DYING_RESCUE` | 体力降到 0 | 有桃/酒/急救的角色 | 桃/酒救援或放弃；放弃后死亡 |
| `BORROW_SWORD_RESOLUTION` | 借刀杀人 | 被借刀者 | 对指定目标出杀，否则交出武器 |

响应窗口由 `InterruptStackManager` 负责 LIFO 弹出。`responseWindow.deadline` 由内核
`timing.response` 盖章；超时沿用 `StackFrame.actionPayload` 的确定性结果。栈帧只保存
JSON 可序列化字段。

### 5.3 无懈可击的奇偶链

普通锦囊使用前，记录 `globalVars.pendingTrick`：

- `wuxieCount` 为偶数：原锦囊生效；
- `wuxieCount` 为奇数：原锦囊被抵消；
- 每张无懈可击把计数 +1，并打开新的 `WUXIE_RESOLUTION`；若无人再响应，按奇偶结算。

这让无懈可击可以递归压栈，同时保持一次 dispatch 只做一次逻辑跃迁。判定区的延时
锦囊在真正判定前也会打开 `JUDGE_TRICK_RESOLUTION`；若被无懈命中，延时牌直接进入
弃牌堆，不进行判定。

### 5.4 玩家选择决策窗口

`过河拆桥`/`顺手牵羊`、`五谷丰登`、`火攻` 需要玩家选择。这里使用内核已有的
单参与者 `DecisionWindow`（`kind: SIMULTANEOUS` + `policy: ALL_COMMITTED`），不新增
内核原语，也不把选择伪装成响应帧。山屋的伤害分配已经使用同一种单参与者决策模式。

- `participants` 只有当前选择者，`getFocusActors()`、回放和超时由内核统一处理；
- 选择者看到 `RESOLVE_CHOICE` 动作，其他玩家看不到具体手牌选项；
- 暗置手牌只暴露“随机手牌”入口，装备/判定区的公开牌逐张列出；
- 选择动作是普通 `reduce`，决策超时由 `onDecisionResolved()` 回退到第一个选项；
- `pendingChoice` 是可序列化的全局上下文，投影时会对非选择者裁剪手牌选项。

### 5.5 自动阶段与 C-2

`resolveFollowUp()` 只在没有打开的决策/响应窗口时返回下一个自动动作；动作类型包括
`START_TURN`、`RESOLVE_JUDGE`、`DRAW_PHASE`、`FINISH_DISCARD`、`FINISH_TURN`。
它们各自进入 `actionLog`，因此不会出现“reduce 里偷偷跑完一整回合”的 C-2 偏离。

## 6. 牌面规则

### 6.1 基本牌

- **杀**：出牌阶段限一次，对攻击范围内一名角色使用。目标需出【闪】，否则受到 1 点伤害。
- **火杀**：普通【杀】的火焰伤害版本；对藤甲角色伤害 +1。
- **雷杀**：普通【杀】的雷电伤害版本。
- **闪**：响应【杀】或【万箭齐发】时打出，抵消之；不能在出牌阶段主动使用。
- **桃**：出牌阶段回复一名已受伤角色 1 点体力；濒死时救助目标。
- **酒**：出牌阶段限一次，下一张【杀】伤害 +1；濒死时对自己回复 1 点体力。

### 6.2 普通锦囊

- **过河拆桥**：弃置目标区域里的一张牌。装备/判定区的公开牌逐张选择；暗置手牌
  只提供“随机手牌”入口，避免通过动作列表泄露牌面。
- **顺手牵羊**：获得距离 1 的目标区域里的一张牌；谦逊角色不可被指定。
- **决斗**：从目标开始轮流打出【杀】，未打出者受到对方造成的 1 点伤害。
- **借刀杀人**：令装备区有武器的目标对其攻击范围内另一名角色出【杀】；拒绝则把武器
  交给使用者。目标选择与受害者选择在同一个动作的 `payload.victimId` 中。目标资格由
  `equipmentOfSlot(state, target, 'WEAPON')` 判断，不硬编码武器 id 清单。
- **无中生有**：摸两张牌。
- **无懈可击**：抵消一张锦囊或另一张无懈可击；见 §5.3。
- **南蛮入侵**：其他所有角色需出【杀】，否则受到使用者 1 点伤害。
- **万箭齐发**：其他所有角色需出【闪】，否则受到使用者 1 点伤害。
- **桃园结义**：所有角色回复 1 点体力，未受伤者不受影响。
- **五谷丰登**：亮出等同存活目标数的牌，按座次每名目标依次选择一张，余牌进弃牌堆。
- **铁索连环**：选择一至两名角色横置或重置；可以重铸（弃置并摸一张）。
- **火攻**：目标随机展示一张手牌；使用者可以弃置一张同花色手牌并造成 1 点火焰伤害，
  也可以放弃。展示牌在选择结算后回到目标手牌。

### 6.3 延时锦囊

- **乐不思蜀**：判定不为红桃则跳过出牌阶段。
- **兵粮寸断**：判定不为梅花则跳过摸牌阶段。
- **闪电**：判定黑桃 2~9 则 3 点雷电伤害，否则移至下家判定区。

延时锦囊在使用时进入 `zone_judge_public` 等待无懈可击窗口；未被抵消后进入目标判定区。
在目标判定阶段、真正进行判定前，还会再次打开一次无懈可击窗口（`JUDGE_TRICK_RESOLUTION`）。

技能规则与响应窗口的对应关系：

- **仁德**：每个 `USE_SKILL` 交出一张手牌；本阶段第 2 张触发回复 1 点体力。

- **刚烈**：受到伤害后进行判定，非红桃令伤害来源失去 1 点体力。

- **谦逊**：不能成为【顺手牵羊】和【乐不思蜀】的目标。
- **连营**：失去最后一张手牌时摸一张（由 `maybeLianying` 统一触发）。

- **无双**：【杀】目标需两张【闪】；决斗中非吕布一方需两张【杀】。
- **离间**：弃一张牌并令两名男性角色进行决斗。

## 8. 应用层接口

规则层只产出可序列化状态和动作；应用层通过以下契约消费：

- `GameModule.legalActions` → `getSanguoshaLegalActions`；
- `GameModule.reduce` → `applySanguoshaAction`；
- `GameModule.resolveFollowUp` → `resolveSanguoshaFollowUp`；
- `GameModule.outcome` → `checkSanguoshaWin`；
- `GameModule.project.player` 负责身份局隐藏非主公身份、阵亡后公开；团队/村规模式角色公开；
- `GameDriverHints.isAutomated` 指向 `globalVars.seats` 中的 AI 座位，`aiActionDelayMs` 让
  app/server 按同一节奏逐步派发 AI 动作；
- 单机 `presentation.defaultViewer` 绑定第一个真人座位，避免上帝视角看到 AI 手牌；
- `GamePresentationHints.cardFacts` / `cardStyle` / `roleLabel` / `describeMoment` /
  `defaultViewer`；
- Presenter 的 `UiAction` 使用标准动作 DTO：`PLAY_STRIKE`、`PLAY_DODGE`、`PLAY_PEACH`、
  `PLAY_CARD`、`EQUIP_CARD`、`USE_SKILL`、`DISCARD_CARD`、`RESOLVE_CHOICE`、`PASS`、`END_TURN`。

`packages/app/src/session.ts` 只负责把状态映射成 `UiPlayer` / `UiAction` / `UiDetailView`，
不执行任何牌局规则；`apps/web` 只绘制 DTO。卡牌文本、身份名、终局幕布和牌面事实均由
`packages/games/src/sanguosha/presentation.ts` 声明，通用层没有新增 `gameId === 'sanguosha'`
的规则分支。

## 9. 实现差异与已知边界

这些差异是**有意保留的模拟器取舍**，不是隐藏规则：

1. **模式边界**：身份局支持 4–8 人（标准 5/8 人），4 人对抗固定 2v2，杀下家支持 2–8 人；
   国战、1V1、3V3、神将/界限突破等仍是内容扩展，不在本状态机内。
2. **牌堆范围**：标准牌堆 108 张 + 可选军争 52 张；不含全部商业扩展与 SP 牌。
3. **过河拆桥/顺手牵羊的手牌选择**：装备/判定区的公开牌逐张选择；暗置手牌只暴露
   “随机手牌”入口，由 `prngState` 随机取一张，不在选择列表中泄露牌名。
4. **自动选择型技能**：洛神、铁骑、刚烈、枭姬、连营等触发技由确定性策略自动执行；
   在完整桌游中它们可能需要“是否发动”的询问。当前实现把它们视为锁定/自动触发，
   以保证无头 bot、回放和单机流程不依赖 UI 弹窗。
5. **木牛流马**：宝物牌与牌下藏牌机制未加入牌堆。
6. **AI 策略**：AI 只读取投影状态，按合法动作做启发式选择（保桃/闪、优先装备与攻击
   低体力目标、响应窗口优先使用响应牌）。它不是搜索型强 AI，也不会读取隐藏身份或
   他人手牌；房间仍可以用真人替换任意 AI 补位。
7. **演示性发牌**：p1 固定获得一张【杀】与一张【八卦阵】，保证首屏有可打的手牌和可
   触发的防具；其余手牌与牌堆仍由 `DeterministicPRNG` 洗牌，不能据此推断全局洗牌偏差。
8. **杀下家目标**：目标在伤害结算前按“当前存活座位环”计算；若下家被第三方或判定伤害
   杀死，原座位的“杀下家”胜利不触发，最后由唯一生还者获胜。

## 10. 扩展方式

新增一张牌时：

1. 在 `cards.ts` 的 `CARD_LIBRARY` 增加 `SgsCardMeta`；
2. 在 `STANDARD_DECK` 或 `MILITARY_DECK` 增加花色/点数种子；
3. 在 `legal.ts` 生成合法目标；
4. 在 `resolve.ts` 增加牌面结算（优先复用 `startTrick` / `beginStrike` / `doDamage`）；
5. 若它是装备，补 `equipSlot`、`range`/`hookId`，并确认 `syncEquipmentHooks` 能重建钩子；
6. 在 `docs/SANGUOSHA.md` 和测试夹具里各补一条事实源，避免文档与代码漂移。

新增武将时：

1. 在 `heroes.ts` 增加 `SgsHero` 和技能描述；
2. 在 `legal.ts` 生成主动技动作；
3. 在 `resolve.ts` 的 `handleUseSkill` / 响应动作 / 伤害钩子中实现结算；
4. 在 `presentation.ts` 不需要新增分支，角色卡从 `customProps.skillNames` 读取；
5. 加一个至少覆盖技能核心分支的测试。
