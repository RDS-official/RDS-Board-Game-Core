# 交互重设计方案：统一动作手牌 + 径向目标选择

> 本文是**技术方案（不含实现）**，用于评审与拆分 PR。
> 上一轮审查见 [INTERACTION-AUDIT.md](INTERACTION-AUDIT.md)；本方案针对其中 G1/G3/G5/G6 的核心症结给出结构性解法。
> 决策来源：用户 2026-11-07 的明确拍板（见 §0）。

---

## 0. 决策记录（本轮已拍板）

| 议题 | 结论 |
| --- | --- |
| 3D 真实手牌 | **保留为只读展示**（不可拖），DOM 统一手牌是**唯一操作入口** |
| 非牌面动作（结束回合/掷骰/移动/抽牌） | 作为**命令卡混入同一手牌**，样式可区分 |
| 目标选择主路径 | **拖动时浮出径向分段选择器**：拖到某分区＝对该目标打出；拖到中心圆＝开二级菜单 |
| 数值类（筹码/标签/金币） | **先甩出动作，再显示数值二级菜单**，确认后才提交 |
| 移动端 | 统一手牌即**底部抽屉/横滑**，全端一致 |
| 操作 deck（动作扇形 dock） | **移除**，其状态/告警/放置面板见 §6 重定位 |

裁定原则：本方案中凡是"可推翻的细化解释"，均标注 **〔裁定〕**，评审时可单独调整，不牵动主体。

## 1. 目标与不变量

**目标**：把"同一份 `snapshot.actions` 被画三遍、绑两套手势"收敛为**单一数据源、单一操作入口、一套手势**。

**不变量（不可破坏）**
1. 通用层不得出现 `meta.id === '<gameId>'`；差异化只走 `UiAction` 字段与 `GamePresentationHints`。
2. `apps/web/src/ui` 只 import `../app/contracts`（`AGENTS.md` §3.1）。
3. 浮层仍以 `OverlayArbiter` 为唯一状态源（`overlay.ts`），新浮层不得直接操作 `#hover-hint` / `#card-sheet-layer`。
4. `GameState` 仍纯 JSON 可序列化；本方案只改表现层与 presenter 契约，**不动 kernel**。
5. 常驻 DOM 面板按 key 复用（`dom/keyed.ts`），不得回到"每次快照整段重建"。

| 现状 | 处置 | 说明 |
| --- | --- | --- |
| `#hand-slot`（侧边手持区） | **删除** | 逻辑并入统一手牌 |

## 3. 统一动作手牌（Unified Action Hand）

### 3.1 数据模型：`UiAction` → 卡片

一张卡由 `UiAction` 派生，**不做游戏特判**：

```
CardModel = {
  id: action.id,                 // 稳定 key
  kind: 'entity' | 'command' | 'numeric',
  icon, label, hint, tone,
  cooldownMs,
  target: {
    mode: 'none'        // 直接执行（长按/松手即打）
        | 'selection'   // 有 selection.candidates → 径向选择器
        | 'placement'   // placementEntityId → 进入放置模式（见 §6）
        | 'fields'      // 有 fields → 二级菜单（含数量滑块）
  },
  art?: string,                  // entity.cardFacts / imageUrl 提供卡面
}
```

`kind` 的判定（**纯能力推导**）〔裁定〕：
- 有 `entityId` 且有卡面 → `entity`（用真实卡图，如扑克/三国杀手牌）；
- 有 `fields`（含 number/slider，如筹码数量）→ `numeric`；
- 其余（END_TURN / ROLL / MOVE / DRAW…）→ `command`（统一图标卡，靠 `icon`+`tone` 区分）。
- `cooldownMs>0` → 卡面加倒计时角标并置灰（沿用现状冷却语义）。

### 3.2 卡面形态

- **entity 卡**：正面卡图（`art`）+ 底部 label/hint；与现有 `cardArt.ts` 复用。
- **command 卡**：图标放大 + label + hint，`tone` 上色（primary/danger）；结束回合这类用 danger/中性固定风格。
- **numeric 卡**：图标 + label + "需选择数量"角标。
- 三类共用同一外框、同一手势；仅视觉分层不同。

### 3.3 布局：炉石式散形

- **复用** `ui/handLayout.ts` 的鱼眼归一化（`handLayout()` 已做到"任意张数、任意指针位置、永不溢出"）。
- 散形 = 每张卡按中心偏移 + 旋转角 + 缩放；指针附近抬起（`HOVER_SCALE` 已有）。三端同一套算法，只是容器宽度不同。
- 卡数很多时（三国杀/Catan 局末）鱼眼自动压缩远端卡片至 22% 可见——这就是我们要的"浏览感"，无需分页。

### 3.4 手势状态机（唯一入口）

```
idle
 ├─ 指针进入手牌 → browse（鱼眼跟随，不发动作）
 │    ├─ 滚轮 / 横向滑动  → 切换焦点卡（复用 cycleHeld 的 24px/40px 阈值）
 │    ├─ 单击             → expand（peek→pinned 看详情，走 OverlayArbiter）
 │    └─ 长按(500ms,环形) → 依 target.mode：
 │          none      → 直接执行（dispatch）
 │          selection → 弹径向选择器（§4）
 │          fields    → 弹二级菜单（§5）
 │ 拖动卡片离开手牌区 → dragging
 │    ├─ 拖到 3D 棋盘目标（房间/卡位）→ 落点高亮 → 松手放置（现有 raycaster 命中）
 │    ├─ 拖出即弹径向选择器（selection 类）→ 松手到分区=对该目标打出
 │    └─ 松手在空白 → 回弹 + "已取消"
```

关键点：
- **单击=看，长按=执行/选择，拖=打**——三者语义分离，直接消灭审查里的 G5（一手势多义）。
- 移动取消阈值沿用 14px；切换/长按复用现有 `handPress` 计时器与环形 SVG。
- "能直接执行的"= `target.mode==='none'`，长按即发；其余一律"慢一拍"进选择，天然满足 G2 的破坏性动作确认。

### 3.5 执行路由（声明式，无 gameId）

```ts
function routeCard(card, gesture) {
  if (card.target.mode === 'none')        return dispatch(card.action);
  if (card.target.mode === 'fields')      return openFieldSheet(card.action);   // §5
  if (card.target.mode === 'placement')   return armPlacement(card.action);     // §6
  if (card.target.mode === 'selection')   return openRadialPicker(card.action); // §4
}
```

`dispatch` 的返回 `{ok, error}` 就是引擎合规结果（`session.ts` 现状），**UI 不自造规则**；失败时按 §5.3 回显。

## 4. 径向目标选择浮窗（Radial Target Picker, RTP）

> 触发：拖动 `selection` 类卡片 / 长按 `selection` 类卡片；候选来自 `action.selection.candidates`（玩家、实体、牌…通用，故玩家对局、指向性卡牌、目标实体同一套）。

### 4.1 出现时机与锚点

- 以**被拖卡片的松手点 / 指针**为圆心浮出，尺寸 `R` 随视口 clamp（保证在小屏不溢出、在大屏不过大）。
- 出现时通过 `OverlayArbiter` 以 `pinned` 语义登记一个**手势浮层**，确保同时关掉所有 peek、且不被新 peek 顶掉。
- 拖动中实时高亮"当前悬停分区"；松手即提交该分区目标。

### 4.2 几何生成（正多边形 + 中心圆 + 顶点抖动 + 分区连线）

确定性生成，**同一次打开只抖一次**（避免拖动中抖动闪烁）：

```
fn buildWheel(candidates, seed):
  n = candidates.length
  // 1) 正 n 边形外轮廓：顶点半径 R，角度均匀
  // 2) 每个顶点做「有界随机」抖动：Δr∈[-0.12R,0.12R]，Δθ∈[-0.18*step,0.18*step]
  //    —— rng 由 hash(seed) 播种，稳定可复现
  // 3) 中心圆半径 r0 = 0.34R
  // 4) 分区 i = 环形扇区：外边界=抖动后多边形第 i 段，内边界=中心圆弧，
  //    两侧边=从中心引到该段两端点的两条直线（即"连线"）
  // 5) 每个分区放候选标签（名字/图标/颜色），文字沿径向排布
```

- `n===1` → 退化为"中心圆 + 单环"，直接指向唯一目标（仍显示名字，避免无反馈）。
- `n` 很大（>8）→ 外接半径自动放大或分层两道环〔裁定：先放大，不做双层环〕。
- 颜色取玩家 `color`；文字描边保证对比度（沿用 a11y 的描边规则）。

### 4.3 命中测试

```
fn hitTest(px, py):
  (dx,dy) = pointer - center
  r = hypot(dx,dy)
  if r < r0: return { zone:'center' }
  θ = atan2(dy,dx) 归一化到 [0,2π)
  i = 找到 θ 落在哪个（抖动后的）扇区
  return { zone:'segment', candidate: candidates[i] }
```

- 扇区角度边界直接用 §4.2 抖动后的顶点角，保证与视觉完全一致（**渲染与命中共用同一几何对象**，杜绝"看着在一个区、判在另一个区"）。
- 拖动过程中用 rAF 合并更新高亮，避免高频重排（同现有 `fanPointerBound` 的合并策略）。

### 4.4 中心圆 = 二级菜单

- 拖到中心圆并松手 → **打开二级菜单**（`fields` 表单 / 目标确认 / 取消），而非直接提交。
- 语义：中心是"我还没定 / 要更多选项"。菜单内容来自 `action.fields` 与 `action.selection.spec`（`min/max` 多选、参数）。
- 多目标（`selection.spec.max>1`）〔裁定〕：径向分区选"第一个"，中心菜单里补齐其余；或长按选择器支持"多选后确认"。优先做单选+中心补全，简单可靠。

### 4.5 数值类动作的特殊顺序

按你的规定：**先甩出动作，再显示数值二级菜单，确认后才提交**。

```
drag(numeric card) → 卡片飞向桌面（视觉"打出"）
                   → 立刻弹出数值面板（slider + 快捷档位）
                   → 确认 → dispatch(action, {amount})
                   → 取消 → 卡片飞回手牌，状态不变
```

- **状态提交仍然在确认之后**，视觉"甩出"只是动效，不回滚风险（`dispatch` 仍由引擎校验）。
- 面板复用现有 `openPayloadForm` 的 slider 能力（`widget:'slider'` / `marks`）。

## 5. 二级菜单与引擎合规

### 5.1 二级菜单形态
- 复用现有 payload 表单（§`openPayloadForm`）与 selection 校验，统一走 `OverlayArbiter` 的 `modal`。
- 内容：参数滑块 / 枚举 / 多选目标补全 / "确认 / 取消"。

### 5.2 合规由引擎判定
- UI 只负责"收集意图 + 目标 + 参数"，**合法性一律交给 `dispatch`**。
- 前端可做"软提示"（候选即合法子集），但**不得**代替引擎判定。

### 5.3 失败回显（补 G6/G11）
- 失败 → 手牌卡轻微 shake + 就近 toast/气泡说明"为什么不行"（`result.error` 已是人话）。
- 非法目标分区在拖动时即置灰（半透明 + 禁止图标），与"选完再报错"相比更早止损。

## 6. 必须保留的既有模块（从 dock 重定位）

移除动作扇形后，dock 内这些**不能丢**，重定位方案：

| 模块 | 现状位置 | 新位置 |
| --- | --- | --- |
| 决策窗口 / 响应栈告警 `alert-strip` | dock 顶部 slot | 手牌上方常驻细条（仍复用 `paintSlot` 签名守卫） |
| 任务目标 `mission` | dock slot | 同上 |
| 楼层页签 `floor-tabs` | dock slot | 行为不变，移到手牌上方或右栏 |
| 状态栏 phase/actor/round/stack/decisions/legal | `dock-bar` | 收进统一手牌的标题行 |
| 放置面板（旋转/确认 + 连线信息） | dock `placement` 模式 | **独立"放置条"**：放置模式下替换手牌区内容（与现状"fan 被 placement 面板替换"一致），并保留世界内 gizmo（`session.ts:460`） |
| 对局结束 / 无动作空态 | dock | 手牌区空态 |

> 原则：**手牌区是"动作入口"，告警/状态是"环境信息"**——两者视觉上分层，但归属同一底部区域，避免再长出第二个面板。

## 7. 响应式与移动端

- **全端同一组件**，三形态：
  - 桌面：底部横排散形，常驻；
  - 平板：横滑条；
  - 手机：底部抽屉，默认露手柄，上滑展开散形（沿用 `UI-RESPONSIVE-PLAN.md` 的抽屉档位）。
- 窄屏手牌卡最小触控 **≥44×44**；长按期间屏蔽页面滚动（`touch-action:none`，仅在手牌区）。
- 径向选择器在手机上以指针为圆心会上移，避开手指遮挡〔裁定：圆心相对指针上移 ~80px〕。

## 8. 可访问性

- 手牌是"可聚焦的卡片列表"：每卡 `role=button`、`aria-keyshortcuts`、`aria-label=label+hint+target`；容器用 roving tabindex。
- 键盘等价路径：`←/→` 切换、`Enter` 打开/执行、`Esc` 取消选择——**径向选择器必须有键盘/列表等价物**（不能只有指针几何命中）。
- 径向选择器提供 `role=menu`（或 `listbox`）的**隐藏线性列表**，读屏可逐项朗读并确认。
- 遵守 `prefers-reduced-motion`：甩出/回弹/鱼眼过渡全压到 0.01ms。

## 10. 验收探针（与现有体系对齐）

- 新增 `probe:hand`：
  - 任意动作数（1 / 5 / 20）散形不溢出、焦点卡可辨识；
  - 单击=详情、长按=执行、拖动=打出的**互斥性**（一次手势只触发一条路径）；
  - 键盘全流程可达（Tab/←→/Enter/Esc）；
- 新增 `probe:radial`：
  - 命中区域与渲染几何一致（随机采样点断言同区）；
  - 中心圆稳定触发二级菜单；单目标直接提交；
  - 抖动确定性（同 seed 两次打开顶点一致）。
- 复用：`probe:a11y`（对比度/可访问名/触控 44）、`probe:dom`（节点复用）、`test:ui`（21 屏）。
- 埋点：动作被拒原因分布、停留在径向选择器的超时次数（BGA："玩家卡在某阶段=设计警告"）。

## 11. 风险与开放问题

1. **DOM 手牌 → 3D 棋盘拖拽的跨域命中**：从 DOM 卡拖到 canvas 需要把 `pointermove` 的 client 坐标喂给 `raycaster.pickAt` 做落点高亮——技术上可行（`pickAt` 已公开），但要新增一条"DOM 拖动代理"，且与 OrbitControls 的禁用/恢复严格配时。**列为 P4 的主要实现难点**。
2. **径向选择器的可访问性**：几何命中天然不利键盘/读屏，§8 的"隐藏线性列表"是硬要求，不能省。
3. **非牌面命令当卡**的认知负担：结束回合做成卡可能让老玩家别扭；用固定位置（最右）+ 固定样式降低学习成本。
4. **3D 只读手牌的信息密度**：去掉其交互后，玩家可能仍想"在桌上摸牌"——保留摸牌动画，只是不可操作〔裁定，可再议〕。
5. **多目标动作**（`max>1`）在径向里如何优雅表达：先做"单选 + 中心补全"，后续再评估多选环。
6. **数值类"先甩后数"与回放/网络同步**：必须保证确认前不 dispatch，否则回放哈希与联机广播会脏。
